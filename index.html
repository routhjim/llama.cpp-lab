llama.cpp, measured on Strix Halo

Changes to llama.cpp for AMD's Ryzen AI Max+ 395 on Vulkan/RADV, each merged through a pull request with a before and after number from this one machine. The negative results are here too.

Two models drive the work: Qwen3.8-Flash-Next, a 180B sparse MoE with hyper-connections and a sparse-attention indexer, on the integrated GPU; and dense Qwen3.8-27B on a 7900 XTX over USB4. None of this is in upstream llama.cpp.

Findings

Where the time goes

~205 ms

per decode step when slots in one verify batch draft different lengths. The batch splits into small ubatches. This, not gating itself, is why per-token p_min gating lost every test on this box.

57% / 21%

of a Flash-Next decode step at np1 is the 8-bit dense path and the MoE experts respectively. With several streams the expert union takes over.

0.389 µs

per token of context on top of a 41.53 ms step: Flash-Next decode at np1 is linear in KV length, with no cliffs.

−5.7% / −0.3%

perplexity from an Engram-style n-gram memory table trained post hoc on a frozen Qwen3.8-27B: −5.7% on held-out text from its training mix, −5.1% on agent prose, but −0.3% on the agent's own shell commands and −0.12% on wikitext. Flash-Next trains its table jointly; this measures the post-hoc case. On gfx1151, fla's Triton gated-DeltaNet backward returns NaN gradients, so train with the PyTorch path.

Build and run

Reproduce it

cmake -B build -DGGML_VULKAN=ON -DGGML_VULKAN_MMV_MAX_COLS=32 -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

MMV_MAX_COLS=32 matters: the default of 16 puts a decode cliff at verify batches above 16.

build/bin/llama-server -m Qwen3.8-Flash-Next-UD-Q4_K_XL-00001-of-00004.gguf \
  -md mtp-Qwen3.8-Flash-Next-Q4DRAFT.gguf --spec-type draft-mtp \
  --spec-draft-n-max 3 --spec-coupled -ngl 99 -ngld 99 -fa on \
  -ctk q8_0 -ctv q8_0 -lm mmap -lzm auto -c 262144 -np 1 --jinja

Always pass -lm mmap for Flash-Next. With auto, one device that lacks mmap turns it off for all of them, and the load then needs the whole file in RAM.

The Flash-Next MTP graph is derived from JJJYmmm's closed upstream PR #27739. The flash-attention dequant change this build carries is Nathanw1014's upstream PR #28190.
